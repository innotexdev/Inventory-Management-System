# Inventory Backend — Milestone 1: Foundations

Express + Prisma (PostgreSQL) skeleton. No auth, no business logic yet.
Milestone 1 = repository setup, folder structure, database schema,
migrations, seed script, README. Auth arrives in Milestone 2.

## Prerequisites

- Node.js 20+
- Docker Desktop (for PostgreSQL), or a local PostgreSQL 15+

## Setup

```bash
cp .env.example .env   # Windows: copy .env.example .env
npm install

# start the database
docker compose up -d

# create the schema (applies prisma/migrations in order)
npm run db:migrate

# fill with seed data (idempotent: safe to run twice)
npm run db:seed

# run the API
npm run dev
```

API: `http://localhost:5000` — health: `http://localhost:5000/api/health`

## Scripts

| Command              | What it does                               |
| -------------------- | ------------------------------------------ |
| `npm run dev`        | Start with hot reload (`tsx watch`)        |
| `npm run build`      | Generate Prisma client + compile to `dist`|
| `npm start`          | Run the compiled server                    |
| `npm run db:migrate` | Apply migrations (`prisma migrate dev`)    |
| `npm run db:seed`    | Seed data (`tsx prisma/seed.ts`)           |
| `npm run db:studio`  | Open Prisma Studio                         |
| `npm run typecheck`  | `tsc --noEmit`                             |
| `npm run lint`       | ESLint (zero warnings)                     |
| `npm run format`     | Prettier check                             |

## Design notes (enforced by migrations)

- **One active assignment rule** is guaranteed by the database, not just app
  code: `assignments_one_active_per_item` is a partial unique index on
  `(itemId) WHERE returnedAt IS NULL`.
- **assetTag** (`INV-0001`, …) is generated by a database sequence
  (`item_asset_tag_seq`) as the column default with an immutability trigger.
- **Case-insensitive uniqueness** for team name, email and serial number via
  expression unique indexes (`lower(...)`); emails also have a
  `CHECK (email = lower(email))`.
- **History is append-only**: assignment FKs are `RESTRICT`. Items are retired,
  users are deactivated. `purchaseDate` cannot be in the future (`CHECK`).
